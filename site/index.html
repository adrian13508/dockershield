Skobel

Docker publishes container ports by writing its own iptables rules. A port mapped with -p 5432:5432 is reachable from outside even when UFW says it is denied (Docker documentation).

Skobel is a read-only command-line scanner for a single Linux host. It is open source (Apache License 2.0) and makes no network requests during a scan.

Source, documentation and releases on GitHub

What it does

  • Lists which container ports are published and on which addresses, and rates them by the service behind the port.
  • Checks whether UFW or the DOCKER-USER chain filters published ports, for IPv4 and IPv6 separately.
  • Reports containers with host networking or a mounted Docker socket, and a Docker daemon listening on TCP.
  • Prints a suggested fix for each finding. It does not change any configuration.
  • probe, run from another machine, connects to the published ports and shows which ones answer.
  • Output as text, JSON, Prometheus metrics or a single-file HTML report.

What it does not do

  • It does not fix anything and does not manage firewall rules.
  • It detects filtering rules; it does not evaluate them. A rule in DOCKER-USER may not cover every port.
  • It does not scan images for vulnerabilities.
  • The full list is in the Limitations section of the README.

Example

From a scan of the deliberately misconfigured test services in the repository:

1. [CRITICAL] Container 'skobel-test-db-1': PostgreSQL published on all interfaces
   Port: 5432/tcp on 0.0.0.0, ::
   Why: Other machines can connect to this port unless a firewall outside Docker blocks it.
        UFW rules do not apply to published container ports by default.
   Fix:
     In compose, bind the port to localhost:
       ports:
         - "127.0.0.1:5432:5432"

The same port checked from a second machine, after it was blocked for IPv4 only:

5432/tcp  (container skobel-test-db-1; expected PostgreSQL; bound on 0.0.0.0, ::)
  192.168.0.2      published but blocked on the way (no answer)
  fd00:d5:d5::2    published and confirmed from outside: PostgreSQL

Skobel for teams (coming soon)

The command-line tool checks one server at a time and keeps no history. A hosted version for people who run several servers is being considered. It is not built. Ideas so far:

  • Scan results of all servers in one place, with history.
  • A notification when a new port becomes published or a finding appears.
  • Checks from outside without needing a second machine.
  • Reports to hand to a client or an auditor.

The command-line tool stays free and open source, and it will not send anything anywhere unless you run a command that says so.
